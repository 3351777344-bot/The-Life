# 默认演示路径

更新时间：2026-05-18
适用分支：`Tilams`

## 1. 演示目标

这份文档用于帮助项目组在答辩、汇报或内部联调时，沿一条最稳定的默认路径完成产品展示。

目标不是展示所有功能，而是展示：

1. 产品完整闭环
2. AIGC 与人生选择的结合方式
3. 路线对比与终局报告的产品价值

## 2. 推荐演示角色

默认用户画像：

1. 年龄：28
2. 学历：本科
3. 职业：互联网产品经理
4. 城市：北京
5. 风险偏好：平衡型
6. 人生目标：职业成长与长期灵活生活

说明：

当前代码默认状态已经和这条演示画像对齐，因此不需要在演示时大幅改动表单内容。

## 3. 推荐展示顺序

### Step 1. 入局

演示重点：

1. 展示基础建模表单
2. 强调产品不是空想，而是基于现实约束做路线推演
3. 在情境卡片中选择一个风格明显的选项，例如“平衡型”

推荐说法：

“产品首先会基于用户真实背景和偏好建立初始人生模型，而不是直接给出泛泛建议。”

### Step 2. 命轨

演示重点：

1. 展示树状人生分支图谱
2. 点击几个节点，说明产品支持把抽象选择可视化
3. 可视情况演示一次快速延伸分支

推荐说法：

“这里不是传统问答，而是把人生关键节点做成可展开、可回看的图谱结构。”

### Step 3. 衍化

演示重点：

1. 展示 AI 路线生成
2. 解释路线有可行性、难度和预期收益
3. 选择两条风格明显不同的路线加入对比
4. 最终选定一条路线

推荐路线组合：

1. 快速成长路线
2. 平衡发展路线

推荐说法：

“产品的价值不是替用户决定，而是把不同路线的差异显性化。”

### Step 4. 对比

演示重点：

1. 展示双窗对比
2. 快速切换一次对比模式
3. 强调不同路线在属性层面的差异

推荐说法：

“同样的用户背景，不同选择会在职业、财务、关系和健康上形成不同走势。”

### Step 5. 观心

演示重点：

1. 展示属性面板
2. 切一次雷达图 / 趋势图 / 影响溯源
3. 说明产品不仅给路线，还给过程反馈

推荐说法：

“这里展示的是选择路径带来的结构性变化，而不是孤立结论。”

### Step 6. 论道

演示重点：

1. 切换一个 AI 角色
2. 输入一个准备好的问题
3. 说明顾问建议会参考当前路线和属性

推荐问题：

1. “如果我选择这条路线，未来一年最需要补什么能力？”
2. “这条路线最大的现实风险是什么？”

推荐说法：

“顾问不是泛泛回答，而是尽量结合当前节点、已选路线和属性状态做建议。”

### Step 7. 归途

演示重点：

1. 展示后悔指数
2. 展示 AI 人生建议
3. 展示旅程统计和已保存路径

推荐说法：

“终局页不是简单总结，而是把整个推演过程压缩成用户能理解、能复盘的一页结果。”

## 4. 演示时尽量避免的操作

1. 不要在答辩现场频繁修改大量基础信息。
2. 不要临时选过多自定义路线。
3. 不要在未选路线的情况下过早跳到终局页。
4. 不要依赖文档上传作为唯一亮点，因为当前它更适合作为补充能力展示。

## 5. 演示时如果出现异常

建议处理方式：

1. 如果场景生成失败，直接说明系统有兜底场景，不影响主流程展示。
2. 如果路线生成失败，可重新触发一次，或切到已有默认路线继续展示。
3. 如果顾问回复失败，可说明当前页面已有错误提示与兜底逻辑，产品仍能继续走完全流程。
4. 如果报告生成失败，可说明终局页已有本地兜底结果，不影响整体产品结构说明。

## 6. 一句话总结

推荐用来收尾的表达：

“这套产品的核心不是预测唯一正确答案，而是把人生分叉中的不同可能性，用 AIGC 可视化、可对比、可复盘地展开给用户。”
