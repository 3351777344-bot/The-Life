# 2026-05-18 Round 01

## 本轮目标

完成前端接管后的第一批基础收口工作，优先解决主流程里最容易影响后续联调和终局展示的状态问题。

## 修改文件

1. `src/App.vue`
2. `src/components/MentorshipView.vue`
3. `src/components/ComparisonView.vue`
4. `src/services/ollamaService.js`

## 改动摘要

### 1. 主流程状态拆分

在 `App.vue` 中把原本混用的生成状态拆开：

1. 路线生成使用独立状态。
2. AI 顾问回复使用独立状态。

这样可以避免一个页面的 loading 状态影响另一个页面。

### 2. 聊天消息结构升级

把论道页聊天数据从“纯字符串数组”升级为“带角色、内容、时间的消息对象”，并让 `MentorshipView.vue` 兼容新结构。

价值：

1. 避免通过消息奇偶位猜测用户和 AI 身份。
2. 为后续问答持久化、节点关联和接口接入打基础。

### 3. 路线选择与对比逻辑整理

统一路线属性影响的读取方式，兼容：

1. `impactFactors`
2. `impacts`
3. fallback 兜底值

同时让对比页和路线选择页对同一条路线的属性理解更一致。

### 4. 终局报告闭环增强

补上终局报告页所需的过程统计：

1. 总选择数
2. 探索时长
3. 成就解锁数
4. 重新开始次数

并在从“论道”进入“归途”时，先调用后悔值计算服务，再进入终局页。

### 5. 重新开始逻辑补全

新增完整的旅程重置逻辑，而不是只切回首页。重置范围包括：

1. 当前路线
2. 树状节点
3. 属性
4. 聊天记录
5. 媒体生成记录
6. 保存路径
7. 页面统计

### 6. 服务层返回格式整理

在 `ollamaService.js` 中增强了结构化结果解析，并统一了 prompt 中上下文的 JSON 序列化方式。

价值：

1. 更适合后续接真实接口。
2. 减少模型返回格式波动对前端的影响。

## 对产品行为的影响

1. 论道页的聊天行为更稳定。
2. 终局报告会更真实地基于当前旅程数据生成。
3. 重新开始会真正进入新一轮旅程，而不是只返回首页。
4. 路线选择、属性变化、对比展示之间的一致性更强。
