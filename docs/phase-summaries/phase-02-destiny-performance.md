# 阶段二：命轨页性能优化

阶段时间：2026-05-18
阶段状态：已完成

## 阶段目标

在不破坏现有视觉和交互体验的前提下，降低命轨页及整体前端构建的首包压力，把性能问题从“模糊的大问题”拆成“明确的可继续优化问题”。

## 本阶段完成内容

### 1. 页面级异步加载落地

主视图改为异步加载，并补统一 loading 占位，减少主包集中度。

### 2. 命轨页 `three` 独立拆包

完成了以下结构变化：

1. `DestinyView` 页面逻辑与 `three` 重依赖分离
2. `three` 变成独立 chunk
3. Vite 手动拆包规则加入 `vendor` / `three` 分离策略

### 3. 命轨页背景保守优化

在保留效果的前提下，对 DNA 背景做了更稳的启用和初始化策略：

1. 只在更合适的设备和屏幕下启用
2. 尊重“减少动态效果”偏好
3. 延后初始化
4. 页面隐藏时暂停动画
5. 页面切换时更完整清理资源

## 阶段成果

这一阶段结束后，性能问题被显著收口：

1. 主入口包下降到较小规模
2. 普通页面拆成轻量 chunk
3. `three` 成为独立、清晰的性能关注点

## 阶段遗留问题

1. `three` 本身仍然是最大的单个 chunk
2. 命轨页虽然更稳，但仍属于较重页面

## 下一阶段切换原因

性能风险已经从“影响整体结构”降为“单点依赖问题”，因此后续优先级切回接口联调准备和主流程产品化收口。
